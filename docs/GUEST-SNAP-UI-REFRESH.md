# GuestSnap UI Refresh Proposal

결혼식 전 빠르게 `GuestSnap` UI를 정리하기 위한 개편 제안 문서입니다.

## 목표

- 하객이 `/guestsnap`에 들어오자마자 **무엇을 해야 하는지** 3초 안에 이해하게 만들기
- 업로드 흐름을 **한 번에 이해되는 구조**로 단순화하기
- 운영자용 기능(QR/포스터)과 하객용 기능(업로드)을 분리해 정보 우선순위를 정리하기
- 결혼식 전 적용 가능한 **저위험 / 고효율 개선안**을 먼저 반영하기

## 범위

- 포함: `/guestsnap` 업로드 전용 페이지
- 포함: 이름 입력 / 파일 선택 / 업로드 진행 UI 구조
- 제외: `/guestsnap/poster` 인쇄용 포스터 자체의 디자인 개편
- 제외: 업로드 API, 스토리지, 세션 정책 변경

## 현재 구조 요약

현재 `/guestsnap` 페이지는 다음 두 영역으로 구성되어 있습니다.

1. 메인 업로드 카드
2. 포스터/QR 카드

그리고 업로드 흐름은 아래 순서로 이어집니다.

1. 업로드 버튼 클릭
2. 이름 입력 모달
3. 업로드 모달
4. 파일 선택
5. 업로드 진행
6. 완료 / 실패 재시도

### 현재 구현 기준 파일

- `src/components/guestsnap/GuestSnapStandalone.tsx`
- `src/components/guestsnap/GuestNameModal.tsx`
- `src/components/guestsnap/UploadModal.tsx`

## 현재 구조의 문제

### 1. 하객용과 운영자용 정보가 한 화면에서 경쟁함

`/guestsnap`은 하객 업로드 페이지인데, 첫 화면에서 QR/포스터 카드가 메인 CTA와 비슷한 무게로 보입니다.

- 하객 입장에서는 “사진을 올리는 곳”인지 바로 이해되면 충분함
- QR/포스터는 운영자나 신랑신부가 주로 쓰는 기능임
- 현재는 보조 정보가 메인 목적을 약하게 만듦

### 2. 실제 플로우는 3단계 이상인데 UI는 모달이 나뉘어 있어 체감이 복잡함

사용자 입장에서는 작업이 하나입니다.

- 이름 입력
- 파일 선택
- 업로드 완료

하지만 현재는 이름 입력 모달과 업로드 모달이 분리되어 있어 “작업이 두 번 시작되는 느낌”이 있습니다.

### 3. 업로드 진행 상태가 충분히 구조화되어 보이지 않음

현재 업로드 진행 UI는 작동은 하지만, 상태 구분이 선명하지 않습니다.

- 선택 완료
- 업로드 중
- 일부 실패
- 전체 완료

이 상태들이 하나의 모달 안에서 연속적으로 바뀌므로, 모바일에서 특히 답답하게 느껴질 수 있습니다.

### 4. 구현 레벨에서도 정리 여지가 있음

- 공용 `Modal` 컴포넌트가 있지만 개별 모달이 스크롤 잠금 / ESC 처리 / 백드롭을 각각 구현
- `UploadQueue`, `UploadProgress` 같은 보조 UI가 존재하지만 현재 메인 플로우에 직접 연결되지 않음

즉, 화면 구조 정리와 코드 구조 정리를 같이 하면 이후 수정 속도도 빨라집니다.

## 개편 방향

핵심 원칙은 아래 한 줄입니다.

> `/guestsnap`은 하객 업로드 전용 화면처럼 보이게 만들고, 운영자 기능은 한 단계 뒤로 뺀다.

### 정보 우선순위

1. 업로드 CTA
2. 업로드 방법과 제한
3. 업로드 진행 상태
4. 운영자용 QR/포스터

## 제안하는 업로드 흐름

업로드 UI는 두 개의 모달 대신 **하나의 연속된 업로드 시트**로 정리하는 것을 권장합니다.

### Step 1. 이름 입력

- 한 문장 설명
- 이름 입력 필드
- 다음 버튼

### Step 2. 파일 선택

- 사진 선택 버튼
- 카메라 촬영 버튼
- 드래그 안내
- 선택된 파일 썸네일
- 현재 선택 개수 / 제한 개수 표시

### Step 3. 업로드 진행

- 전체 진행률 바
- 현재 업로드 파일명
- 실패 시 재시도 CTA
- 완료 시 종료 CTA

## 추천하는 UI 정리 우선순위

### Phase 1. 결혼식 전 빠른 정리

적용 우선순위가 가장 높습니다.

- `/guestsnap` 첫 화면을 업로드 중심으로 재배치
- QR/포스터 영역을 하단 보조 섹션으로 이동
- 업로드 제한 정보 표시 추가
- 3단계 안내 블록 추가
- 모바일에서 메인 CTA를 더 강하게 보이도록 조정

### Phase 2. 플로우 단순화

- 이름 입력과 업로드를 하나의 시트로 통합
- 업로드 상태 화면 구조 정리
- 성공 / 실패 / 재시도 상태를 더 분명하게 구분

### Phase 3. 코드 구조 정리

- `Modal` 공통 사용으로 중복 제거
- 미사용 또는 반쯤 연결된 업로드 보조 컴포넌트 정리
- 초대장 내 GuestSnap 섹션과 tone / copy / flow 일관성 점검

## 제안 카피 방향

현재 감성 톤은 유지하되, 첫 화면에서는 설명보다 행동 유도가 먼저 보여야 합니다.

예시:

- 제목: `퇴장 전, 찍어주신 사진을 바로 올려주세요`
- 보조 문구: `예식 사진과 영상은 예식 후 정리해 신랑신부에게 전달됩니다`
- CTA: `사진/영상 올리기`
- 보조 정보: `사진 30MB 이하 · 영상 500MB 이하 · 최대 N개`

## 최종 권장안

결혼식 전 일정이 촉박한 상황이라면 아래 조합이 가장 현실적입니다.

1. 첫 화면에서 QR 카드 비중 낮추기
2. 업로드 규칙과 3단계 안내 추가
3. 업로드 플로우를 하나의 시트 구조로 정리

이 세 가지만 적용해도 체감 완성도가 크게 올라갈 가능성이 높습니다.
